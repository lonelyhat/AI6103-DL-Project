8 条重试中有 2 条成功解析，一条保留了事实，另一条从带有额外文字的输出中提取到空列表。另有 **6 条**返回拒答或任务外文字，解析字段为 `none`。最终汇总将这 6 条记为 `extracted` 并交付空列表，审计结果单列了对应原始键及轮次。汇报时将它们计作已观测到的解析失败。由于早期尝试记录不全，无法据此计算全部尝试的失败率。继续使用现有开发产物时按原缓存复跑，后续事实质量与成本汇总应保留失败标记。

## 正式批次的下游接口核验

以 `main@3523260` 为快照复算。A03、B04、B06 使用同一份正式题清单和同一份公开历史。两套候选均按清单顺序覆盖 **80 题**，每题各有 100 条可在原历史定位的轮次，每套 **8,000 条候选**。两套检索的模型、代码、软件及非索引配置一致。K0/K1 每题候选平均重合 **82.575/100**，范围 71–93。

C04 的 **18,892 个事实键**可追溯到 A03 用户消息，B06 实际消费的 **19,606 条轮次**逐条与归档事实、来源 ID 和哈希对齐。涉及复用的 **687 个跨题共享键**均对上原文。C04 的 5 条旧格式事实是字符串，清单的 `n_facts` 记录的是字符数。B06 正确把每条字符串转换为一个事实，候选无需因此重跑。后续汇总事实条数时，应使用规范化后的数量。

本节结论对应 v1 快照。G02 曾用 `formal / a03-v1` 完成每题十种材料的 CPU 接口检查。新版题单及候选的状态见 [G02 执行清单](../G02/README.md)。

可从同一 Git 快照复跑这项检查，脚本读取 Git 中的文件，不需要切换分支或使用 GPU。[机器可读核验结果](audit_formal.json)
