# D02：相关性选择与预算材料构建

## 目标与流程

D02将B02的检索候选转换为回答模型可阅读的历史材料，以2048 Token为主预算，保持完整原始轮次，并记录选择、长度和来源。

流程为：候选与公开原文关联 → 按相关性排名逐项试放 → 时间排序与消息去重 → 完整材料计数 → 保存阅读文本和选择记录。

D02使用相关性基线R，复用D01的输入约束、序列化和分词计数规则。输入遵循A01-v2；材料构建不使用参考答案或证据标记。

## 相关性选择规则

候选按rank从小到大扫描，每条只访问一次。将候选加入已选集合，重新构造完整历史文本；实际长度不超过2048 Token时选中，超过预算则跳过并继续处理后续排名。

放不下的候选永久跳过。流程不因某条超长或当前长度恰好达到预算而提前终止，因为去重和分词可能产生零或负的新增成本。停止原因为候选全部处理完或候选列表为空。

rank决定R的访问顺序，原始检索score用于追溯，不重新排序或引入去重、长度、覆盖奖励。该规则采用独立的`d02-v1`标识，与D01逐步重新考察可行项的R区分。

## 时间顺序与轮次身份

轮次ID只负责定位，不能表示时间先后。材料按A01-v2的三级排序键排列：

`sort_key = [session_datetime, session_index, 用户消息位置]`

实际日期时间决定主要顺序，同一时刻按原会话位置、用户消息位置排列。选择顺序与阅读顺序分别保存，既保留检索优先级，也保持历史叙述的时间顺序。

这一设计处理历史会话日期倒序和相同时间戳的情况，适用于新旧知识更新、跨会话比较和时间推理问题。

## 重叠轮次与消息去重

轮次定义为“用户消息＋紧邻下一条消息”。连续用户消息可能使同一条消息属于多个轮次。材料采用选中轮次所含消息ID的并集，每条共享消息只展示一次；不同message_id的相同文本仍保留。

去重不取消轮次身份。`selected_turn_ids`保留选中的全部轮次，`selected_message_ids`记录最终消息集合，A02据此按消息并集评价证据保留。被选中轮次的每条消息都完整存在于材料中。

## 长度与预算口径

每条候选记录两种长度：

| 字段 | 定义 | 用途 |
| --- | --- | --- |
| standalone_context_tokens | 该轮独立序列化后的长度 | 识别单轮超长 |
| proposed_context_tokens | 已选集合加入该轮，排序去重后的总长度 | 决定是否选中 |

独立轮次长度不能直接相加作为预算。候选与已选轮共享消息时，实际新增成本可能较低；即使该轮独立展示时超长，整体去重后仍可能放得下。

材料采用统一的日期标题、角色与JSON消息正文，计数包含标题和分隔符，不截断正文。分词器与回答模型对应，历史编码不添加特殊Token。问题、聊天模板、日期提示和回答额度由回答环节分别预留，2048 Token仅表示历史阅读预算。

## 输入接口

首批开发题包括`2318644b`、`1cea1afa`、`gpt4_7a0daae1`、`4c36ccef`和`c960da58`。

| 数据来源 | 内容 |
| --- | --- |
| B02候选记录 | question_id、stage=dev、index=K0、config_version=a01-v2、candidates |
| candidates | 每项包含turn_id、rank、score，每题最多100条 |
| A01公开问题表 | question、question_date及问题归属 |
| A01公开轮次 | 原始消息、message_id、会话日期与sort_key |
| 实验配置 | strategy=R、budget_tokens=2048、回答模型分词器标识 |

rank为唯一正整数，score为有限数值；候选轮次属于对应问题。首批问题记录完整且不重复，候选与公开问题中的重复元数据保持一致。缺失分数、错误ID、冲突消息或版本不一致属于输入错误。

预算字段可为空或2048，进入选择前统一为2048；声明其他预算的输入与当前实验条件不一致。分词器标签、实际加载来源及内容指纹共同用于标识计数条件。

输入只包含本组匿名位置ID与公开原文。官方ID映射由检索端处理，证据标记和参考答案保留在评价环节。

## 输出与过程记录

每个问题保存阅读文本、逐题选择记录及批次来源信息。

| 内容 | 核心字段或文件 |
| --- | --- |
| 实验条件 | question_id、stage、index、strategy、budget_tokens、tokenizer、config_version |
| 轮次选择 | selected_turn_ids、selection_order、skipped_turn_ids |
| 消息集合 | selected_message_ids、去重消息数量 |
| 实际材料 | history_text、context_tokens、history_sha256及对应txt文本 |
| 逐候选试放 | candidate_trials，含rank、原score、试放前后长度、边际Token、去重ID与决策原因 |
| 选中步骤 | steps |
| 长度异常 | 单轮超长列表、预算不足记录、空材料状态 |
| 来源追溯 | 输入文件、配置、源码及分词器指纹，选择耗时 |

空材料单独标记，不与可供回答的非空材料混同。预算检查记录与独立验收状态分开保存，材料成功生成不等于问答或证据评价通过。

逐题记录集中在`selections.jsonl`，可读材料存于`materials/`，批次信息存于`batch_manifest.json`。整批材料在完整生成后作为同一批次保存，来源文件发生变化时不形成有效交付。

## 与回答和评价环节的关系

E02使用保存的实际阅读文本，保持选择结果与预算口径一致。再次按top-K截取或截断历史会改变材料集合，因此不属于同一份选择结果。

A02依据`selected_turn_ids`对应的消息ID并集统计证据保留，避免重叠轮重复计数。D02提供可追溯的材料和选择过程，不根据证据、参考答案或最终正确率调整选材。

时间顺序、共享消息去重、完整消息保留、最终Token长度及材料哈希共同构成材料一致性的判断依据。真实候选与对应读者分词器是评估该流程的必要输入；合成候选或其他模型的计数不能代替正式条件下的结果。
