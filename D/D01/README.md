# D01：五种历史对话选择方法

## 研究目标

D01为固定预算的长期对话问答提供统一选择模块。模块从检索候选中挑选完整历史轮次，控制阅读材料长度，并记录选择过程，使不同方法的效果能够在相同条件下比较。

官方LongMemEval提供相关性排序、前K条截取和阅读材料构造逻辑。固定预算选择在此基础上增加逐项成本判断，并区分相关性、去重、长度和覆盖四类因素。

## 五种选择方法

| 方法 | 选择准则 | 比较目的 |
| --- | --- | --- |
| R：相关性优先 | 优先选择预算内排名靠前的候选 | 常规预算基线 |
| MMR：最大边际相关性 | `r − λd` | 检查减少重复内容的作用 |
| C：兼顾长度 | `(r − λd) / c` | 检查收益是否来自更高的空间利用率 |
| Q：问题线索覆盖 | `(r − λd + γg) / c` | 检查新增问题线索的独立价值 |
| FL：设施选址式覆盖 | `ΔF(S, i) / c` | 与候选集合代表性覆盖比较 |

同题同索引下，五种方法共享候选和原文。K0与K1分别检索，因而候选及排名可以不同，但相似度、问题线索、序列化和计数规则保持一致。

## 计分定义

`r`为候选检索分数的min-max归一化值，范围为[0,1]；同题候选分数全部相等时统一取1。检索分数是有限数值，排名不代替分数。

`d`为当前轮次与已选轮次之间的最大TF-IDF余弦相似度，范围为[0,1]。文本包含用户消息及紧邻下一条消息，特征不包含索引扩展事实。词频使用原始计数，逆文档频率为：

`IDF(w) = log((1 + N) / (1 + df(w))) + 1`

词法特征包括小写英文单词、数字及单个汉字，不进行词干化、同义词扩展或代词消解。TF-IDF在各自候选集合上计算；K0/K1候选不同时，词表和IDF可以不同。

`g`为新覆盖的问题线索数除以全部问题线索数。问题线索来自固定词法规则和停用词表；已覆盖线索不重复奖励，无线索时取0。这种匹配可以识别明确出现的词面线索，但难以处理隐含关系和同义表达。

`c`来自加入候选后的实际历史Token增量。每次试放均重新排序、去重和拼接，计算包含标题、角色与分隔符的完整文本长度。计分分母取`max(1, Token增量)`，处理重叠消息和非加性分词造成的零或负增量；预算判断仍使用实际总长度。

FL使用相关性加权设施选址目标：

`F(S) = sum_j r_j × max_{i∈S} sim(j,i)`

空集合覆盖为0，选择分数是加入候选带来的目标增量除以新增成本。该对照是项目按上述公式实现的设施选址方法，不等同于PACMS具体配置的逐项复现。

默认参数λ=0.5、γ=0.5是实现初值，不代表开发集上的最优配置。Q在γ=0且其余条件相同时与C一致，可用于覆盖奖励消融。

## 选择与停止规则

R在每一步选择排名最靠前的可放入项，持续填充预算。MMR、C、Q和FL从可行候选中选择分数最高者，最大可行分数不大于0时停止；所有方法在候选耗尽或没有候选能放入时停止。并列时优先较小rank。

D02采用一次扫描、超预算永久跳过的R流程。它与D01逐步重新考虑可行候选的R在非单调分词情况下可能不同，采用独立配置标识；正式比较需要固定统一的R定义。

## 输入接口

输入对齐A01-v2，分为逐题候选记录和公开原始轮次。

| 数据 | 核心字段 |
| --- | --- |
| 问题与配置 | question_id、question、question_date、stage、index、budget_tokens、tokenizer、config_version |
| 候选 | candidates，每项含turn_id、rank、score |
| 原始轮次 | turn_id、session_index、session_date、session_datetime、sort_key、messages |
| 原始消息 | message_id、role、content |

每题最多100个候选。轮次ID与rank分别唯一，候选属于当前问题，重复命中由检索端合并。问题文本和日期可与A01公开问题表关联。

选择模块只接收匿名位置ID及公开原文，不读取官方ID映射、证据标记、题型或参考答案。字段约束见[输入格式](schemas/request.schema.json)和[公开轮次格式](schemas/public_turn.schema.json)；同题对应、共享消息一致性和实际预算属于跨字段约束。

## 时间、去重与阅读预算

一轮定义为用户消息及紧邻下一条消息。连续用户消息会形成重叠轮次，因此轮次集合与消息集合并非一一对应。

材料按`[session_datetime, session_index, 用户消息位置]`排序。消息按message_id去重；不同ID的相同文本保留。去重后的消息并集包含所有选中轮次的原文，不截断消息正文。

预算只覆盖序列化历史材料，分词器与回答模型对应，计数不添加模型特殊Token。问题、聊天模板和回答输出额度属于阅读模型的其他上下文开销，与历史预算分别记录。

## 输出接口

每个问题、索引与策略组合对应一条选择记录。

| 字段 | 含义 |
| --- | --- |
| question_id、stage、index、strategy、budget_tokens、tokenizer | 公共实验条件 |
| config_version、config_id、config | 实现版本、计分规则、参数与分词器指纹 |
| input_sha256 | 问题、候选和原文的来源标识 |
| selected_turn_ids、selection_order | 材料时间顺序与算法选择顺序 |
| selected_message_ids | 去重后的消息集合 |
| history_text、history_sha256、context_tokens | 实际阅读材料、文本指纹与长度 |
| skipped_turn_ids、skipped | 未选轮次、试放长度及原因 |
| steps | 相关性、重复度、覆盖增量、选择分数和成本 |
| stop_reason、question_clues、covered_clues | 停止原因与线索覆盖 |

完整结构见[输出格式](schemas/selection.schema.json)。回答环节使用记录中的实际材料；证据评价根据选中轮次所含消息ID并集统计保留情况。

## 示例与解释范围

房租示例包含新月租1500、重复的新月租1500、旧月租2000及超长无关记录。在282字符预算、λ=1、γ=1下，选择结果为：

| 方法 | 选中内容 | 材料长度 |
| --- | --- | --- |
| R | 两条新房租记录 | 281字符 |
| MMR | 新房租与旧房租 | 282字符 |
| C | 新房租与旧房租 | 282字符 |
| Q | 新房租与旧房租 | 282字符 |
| FL | 新房租与旧房租 | 282字符 |

该例说明相关性排名可能保留重复材料，而去重和覆盖可以保留不同信息。字符预算用于展示算法行为，不能视为真实模型Token数。对应输入和逐步记录保存在[示例汇总](examples/summary.json)。

同一例子使用Qwen2.5-1.5B-Instruct分词器时，预算与各方法材料长度均为107 Token，选中内容保持一致。另有首批5题公开历史构成的25条接口样例，材料长度均不超过2048 Token。其候选分数为合成词面重合分数，因此这些结果仅说明接口与预算行为，不构成检索效果或问答正确率结论。
