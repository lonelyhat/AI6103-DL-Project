## 4. 现有输入输出

### 检索输出

batch_get_retrieved_context_and_eval 返回逐题对象列表，main 将每题对象写成一行 JSON。字段包括 question_id、question_type、question、answer、question_date、haystack_dates、haystack_sessions、haystack_session_ids、answer_session_ids 和 retrieval_results。

retrieval_results 包含 query、ranked_items 和 metrics。ranked_items 每项只有 corpus_id、text、timestamp；排名由列表顺序体现。

**没有保存数值相关性分数。** run_flat_retrieval 内部计算分数，但仅返回排序索引；后续需要 r 的方法须明确如何保留或获得分数，不能把名次直接当 r。

官方输出完整排名，没有先限制成统一前100条候选。后续需定义截取阶段，以及索引扩展重复命中同一轮次时的去重与截取顺序。

### 索引与原文轮次映射

- turn 索引只包含用户消息；ID 后缀为消息在会话全部消息中的1基位置，不是用户发言序号。因此交替对话中的用户消息可能编号为1、3、5。
- flat-turn 从 ID 恢复用户消息，附上存在的紧邻下一条消息；代码没有再验证下一条的 role 必须为 assistant。
- 阅读映射会把 noans_ 替换成 answer_，不能直接按原字符串等值连接。
- 阅读材料清理阶段删除 has_answer。参考答案和证据标记应留在评价端，不能用于选择特征。

### 阅读函数

prepare_prompt 接收 entry、retriever_type、topk_context、useronly、history_format、cot、tokenizer、tokenizer_backend、max_retrieval_length、merge_key_expansion_into_value，以及可选 con 参数，返回最终 prompt 字符串。

它不返回选中 ID、逐项成本、分数或预算日志。topk_context 控制条数；main 按 model_max_length − gen_length − 1000 计算历史长度上限，没有独立2048 Token主预算参数。gen_length 默认表达式使用字符串 args.cot 的真假，字符串 'false' 也是真值，不能仅据该表达式认定 direct 模式默认输出500 Token。

超长时截断已经按时间排序的历史前缀，可能切断轮次或丢掉较晚日期的高排名材料。排序使用会话日期字符串，同一天没有独立的原始消息位置排序键。

### 建议的统一选择接口（仅文档约定，尚未实现）

输入：question_id、question、index_id、candidates、budget_tokens、config。

每条 candidate 至少有：稳定 candidate_id、关联 source_corpus_ids、原始 session_id 和消息下标、timestamp、rank、relevance_score、完整 messages。内部消息下标建议统一0基，rank明确为1基。数值分数来源与归一化规则待后续确定。

输出：question_id、index_id、strategy、selected_candidate_ids、selected_rounds、history_text、actual_history_tokens、selection_trace、config_id。

selection_trace 保存每步分数、成本、跳过和停止原因。选中清单保留选择顺序，展示材料按日期与原始位置排序。成本使用回答模型 tokenizer，包含日期、标签和分隔符，最终拼接后再次检查预算，不能只累加正文长度。

该建议需与 A01 以及 B/E 两端对齐，不宣称已经达成统一格式。选择输入不提供参考答案或证据标注。K1 事实只用于索引时，阅读端建议使用 merge_key_expansion_into_value=none；本次没有验证完整 K1 运行配置。

## 5. 小例子结果

同目录 D01_official_examples.json 保存了实际输入与输出观察。

验证方式：从 Git HEAD 提取官方 prepare_prompt 和 process_item_flat_index 的 AST，在内存中直接执行原函数。没有导入模型运行器、调用模型、下载资源、使用 GPU 或运行 reproduction，也没有保存测试程序。

构造旧房租2000（2024年）与新房租1500（2025年）两段历史，检索排名先新后旧。

| 检查 | 实际结果 |
| --- | --- |
| topk_context=1 | 仅留下新房租和相邻助手回复 |
| topk_context=2 | 旧房租排到新房租前面，has_answer 被移除 |
| 使用 noans_old_1 命中 | 正确回查 answer_old 原始会话 |
| 限制历史长度为110字符 | 截断在旧轮次中间，新房租丢失 |
| flat-turn 且 useronly=True | 复现 TypeError: list indices must be integers or slices, not str |
| turn 索引构造 | 只生成用户正文和 answer_old_1，未编码助手正文 |

截断例子明确使用字符 tokenizer 替身，110字符不等于110个真实模型 Token；只验证前缀截断行为。六个检查均符合预期，其中一个是成功复现官方错误，不表示该配置可用。完整轮次阅读后续应使用 useronly=False。

这些例子没有验证真实检索排序、真实 Token 数、回答质量或五策略效果；缺失方法无法提供运行结果。
