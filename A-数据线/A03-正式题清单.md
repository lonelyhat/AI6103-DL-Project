## 筛选与抽样

1. 校验数据 SHA-256 与 A01 一致，排除全部 40 道 A01 开发题，包括其中的 6 道拒答题。再排除剩余 24 道拒答题。可回答题须存在消息级证据标注。
2. 每题取官方标注证据会话和 A02 消息级证据所在会话的并集。两题共享官方会话 ID 或同一完整会话原文（按角色和内容顺序计算 SHA-256）时连边。以连通分量为证据组，排除与已用题同组的题（v2 为 28 题）。该规则覆盖同一会话中的不同证据消息。组号是该组件字典序最小的题号。
3. 从剩余 232 题按题型比例分配 80 个名额，向下取整后按最大余数补齐，余数相同按题型名称排序。按固定 `SHA-256("a03-v1:" + question_id)` 顺序抽取（v2 沿用 v1 的抽样顺序，只有排除范围变化），以便复跑并避免根据模型表现选题。未抽中的 152 题在审计中标记 `not_sampled`。
4. 证据不可达仍按 A02 口径记录。全量 3 道带不可达证据的题均未抽中。抽样前未以检索排名、证据保留率或回答结果筛题。

| 题型 | 可抽样 | 入选 |
| --- | ---: | ---: |
| knowledge-update | 31 | 11 |
| multi-session | 77 | 26 |
| single-session-assistant | 20 | 7 |
| single-session-preference | 0 | 0 |
| single-session-user | 26 | 9 |
| temporal-reasoning | 78 | 27 |
| **合计** | **232** | **80** |

80 题对应 78 个证据组。`89941a93` 与 `89941a94`、`gpt4_468eb063` 与 `gpt4_468eb064` 各属同一组，F06 计算置信区间时应按同组处理。

## 复跑

在项目根目录运行。

```bash
python3 "A-数据线/A03/build_a03.py" data/longmemeval_s_cleaned.json \
  --extra-used-file "A-数据线/A03/extra_used_ids_baseline_v1.txt"
```

若再补报额外用题，可追加 `--extra-used-id <题号>` 或 `--extra-used-file <文件>`，受影响的证据组会自动排除。正式下游启动前，将确认后的清单版本和数据指纹与组员同步。
