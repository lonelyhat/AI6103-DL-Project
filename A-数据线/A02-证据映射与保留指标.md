## 1. 口径

**以消息级 `has_answer` 为准，不用官方轮级标记。**

一条证据消息被视为“保留”，当且仅当它所在的轮出现在给定的轮列表里（候选列表或选中列表都可以）。

| 指标 | 定义 |
| --- | --- |
| `msg_retention` | 保留的证据消息数 / 全部证据消息数 |
| `all_retained` | 全部证据消息都被保留（“证据齐全”） |
| `any_retained` | 至少保留一条 |
| `n_retained_turns` / `n_evidence_turns` | 轮级计数，供参考 |
| `missing_message_ids` | 丢失的证据消息，便于 A05 找案例 |

- **不可达证据**（不属于任何轮的证据消息）计入分母，因此相关题永远不可能“证据齐全”，归因为“候选没有找齐”。开发题中没有这种情况，全部 500 题中有 3 题。
- **拒答题**（`_abs`）不参与平均。注意：部分拒答题也带 `has_answer`（如 `982b5123_abs`、`e5ba910e_abs`），不能用“有没有证据”来判断是否为拒答题，要用 `is_abstention`。
- 平均值请先按 `(stage, index, strategy, budget_tokens)` 分组再计算。

### 为什么不用官方轮级标记

官方只检查**用户消息**有无 `has_answer`。证据在助手回复里时，这一轮会被标成 `noans`，即“不是证据”。核对结果：

> **6 道 single-session-assistant 开发题中，有 5 道在官方口径下证据轮数为 0**：`4c36ccef`、`71a3fd6b`、`c4f10528`、`c7cf7dfd`、`fea54f57`。（第 6 道 `4388e9dd` 的证据恰好在用户消息里。）

如果沿用官方的 recall 统计，这类题会出现“没有证据可找”，证据保留率无从谈起，K0 在这类题上的检索盲区也就被掩盖了。其余 29 道可回答开发题，两种口径完全一致。

## 2. 用法

### 批量计算（命令行）

输入是 A01 第 4.3 节格式的 jsonl，每行一题一个设置：

```bash
# 选中材料
python3 A02/evidence_metrics.py --input selections/dev_K0_Q_2048.jsonl --output metrics/dev_K0_Q_2048.jsonl
# 候选（取每项的 turn_id）
python3 A02/evidence_metrics.py --input candidates/dev_K0.jsonl --field candidates --output metrics/dev_K0_cand.jsonl
```

终端会打印汇总，输出文件逐行保留公共字段并附加上述指标。样例见 `A02/examples/`。

### 在代码里调用

```python
from evidence_metrics import Evidence
E = Evidence()                                   # 默认读 ../A01/output
E.retention("2318644b", selected_turn_ids)       # → dict
E.official_to_turn("2318644b", "answer_eaa8e3ef_1_1")   # 官方 ID → 本组 turn_id
E.diagnose(qid, candidate_ids, selected_ids, turn_tokens, budget=2048)
```

- `official_to_turn` 会把 `answer_` / `noans_` 统一后再查，两种写法都能对上；**查不到时直接报错**，不静默跳过（对应 B01 第 7 节第 8 条）。
- `retention` 发现混入别题的轮 ID 时会直接报错。
- 正式题：A03 定清单后，用 `build_a01.build_question()` 生成同格式的评价行和映射，再用 `E.add_eval_rows()` 加入即可。

### 错误环节归因（A04 直接使用）

| 返回值 | 含义 |
| --- | --- |
| `candidates_missing` | 候选里没有找齐证据（含不可达证据） |
| `over_budget` | 证据都在候选里，但证据轮完整长度之和超过预算 |
| `selection_missed` | 证据放得下，但没有选齐 |
| `all_retained` | 证据全部留下；若仍答错，问题在阅读、提取或评分 |

`over_budget` 需要传入每轮的 token 数（`turn_tokens`）和预算；token 数应按 D02 的实际渲染格式计数。不传时，无法区分“放不下”与“没选到”，统一返回 `selection_missed`。

## 4. 需要相关同学知道

- **B02 / B05**：拿到官方检索日志后，用 `official_to_turn` 转成 `turn_id`，交给 D 线的文件**只保留 `turn_id`**。同一轮在候选里只出现一次。
- **F02 / A04**：证据统计使用本程序的口径，**不要用官方检索脚本内置的 turn 级 recall**，原因见第 1 节。
- **A03**：开发题里没有不可达证据，但正式题可能会有（全量中有 3 题）。是否保留由 A03 决定，若保留则按本程序口径计入。
