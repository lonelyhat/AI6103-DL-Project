核对基准：main `1826385`，2026-11-02。本文区分团队计划、仓库交付和本次准备；不把尚未跑出的结果当作实验结论。

## 1. 项目要解决什么问题？

聊天助手的历史对话很长，而模型一次只能读有限的材料。如果问题需要两条信息，比如分别找到东京和夏威夷的住宿价格，只读到其中一个价格就无法算出差价。即使最相关的几条内容都谈到夏威夷，也可能因为重复而占满预算，漏掉东京的记录。

项目研究：**在相同阅读预算下，先怎样检索，再怎样挑选原始对话，才能改善回答？**它不是训练一个新的聊天大模型，而是围绕已有数据、检索模型、选择算法和回答模型做受控实验。

LongMemEval-S 提供问题、历史对话及用于评价的答案和证据标注。开发题用于调试；之后正式题要排除开发题，不能用答案或证据标注来挑材料。完整主实验规模、模型和预算都是计划，需以团队最终冻结配置为准。

## 2. 数据怎样流动？

```text
历史对话 ──> K0 或 K1 索引 ──> 每题前 100 条候选 ──> 预算内选择 ──> 回答 ──> 评分
              B / C              B02             D02 等       E02      F02
                                                      ↑
                                A01 提供题目和公开原文；A02/F 使用证据标注检查保留情况
```

- **K0 原文索引**：只用历史中的用户发言建立检索表示。检索到某条用户发言后，交接的编号指向完整原始轮次，包括该用户消息和紧接着的一条消息。
- **K1 事实增强索引**：从历史用户发言抽取事实，将事实用于增强检索；回答时仍阅读完整原始对话，不直接把抽出的事实冒充原文。
- **候选**：不是最终给模型的材料，而是相关性较高的备选轮次。你的 B02 做 K0 的候选。
- **预算内选择**：例如 2048 token 下，不一定能装下全部候选。R 按相关性选；MMR 兼顾去重；C 还考虑长度；Q 奖励新问题线索；FL 尝试覆盖候选的不同内容。具体实现和参数应由 D 线开发、试验并固定。
- **回答与评分**：E 线用选出的原文生成答案，F 线根据规则评分；A02 还统计候选和选中材料分别保留了多少标注证据。

相关性分数衡量问题与用户发言在向量空间中的相似程度；分数高不代表答案一定正确，也不代表完整证据已经找齐。

## 4. 你的 B02：一题怎么处理？

1. 从 A01 的 `public/dev_questions.jsonl` 取问题，从 `public/turns/{question_id}.jsonl` 取历史轮次。
2. 把每个轮次的第一条用户发言作为检索文本，保留它对应的无泄漏 `turn_id`。轮次可能有一条或两条消息，连续用户发言会产生重叠轮。
3. 用 Stella 分别将问题和用户发言编码为向量。此处对齐官方源码中的设置：最长 512 token、平均池化、1024 维投影、L2 归一化，然后计算向量点积并按分数降序排序。
4. 取前 100 个，写出 ID、从 1 开始的排名和分数。每题一行，一共五行。
5. D 线可用 ID 关联 A01 的公开轮次文件取完整原文。交接时要一并说明必须提供这五个公开轮次文件；具体消费者是否支持关联读取，须与 D 线确认。

公开候选只包含题号、本组轮次 ID 和分数，不放参考答案、官方会话 ID、题型或证据标记。`map/` 与 `eval/` 只供允许的映射/评价环节，不进入下游选择和回答。

官方检索源码位于项目目录下（与 `repository/` 平级）的 `B-检索线/官方代码/LongMemEval/src/retrieval/run_retrieval.py`，重点是 `run_flat_retrieval` 和 `process_item_flat_index`。检索用户发言不代表最终只阅读用户发言；被命中的完整轮次由 A01 公开文件提供。

## 6. 怎么运行？

在仓库根目录运行无 GPU 输入检查：

```bash
python3 'B-检索线/B02/retrieve_k0.py' --validate-inputs
```

在准备好 CUDA、依赖和完整 Stella 模型的 GPU 环境中，示例：

```bash
python -u 'B-检索线/B02/retrieve_k0.py' \
  --model-dir "$HOME/B02/dunzhang_stella_en_1.5B_v5" \
  --output "$HOME/B02/results/dev_K0.jsonl"
```

实际目录以集群存放位置为准。实际环境使用 PyTorch 2.11.0+cu128、transformers 4.43.3、NumPy 1.26.4、scikit-learn 1.9.1；程序只读取本地模型。要求 `2_Dense_1024/pytorch_model.bin`，与官方代码一致。默认 batch size 64；显存不够可增加 `--batch-size 8`，但变更 batch size 对数值和排名的影响要实测。GPU 任务应通过学校 Slurm 提交；partition、QoS、环境和路径须以用户账户的实际配置为准。

该脚本直接读取仓库中 A01 已生成的五题公开数据，因此 B02 检索本身不直接读取完整原始数据集；完整数据集仍是重建 A01、官方基线核验等工作所需。下载完应与 `dev_manifest.json` 中的 SHA-256 校验。
