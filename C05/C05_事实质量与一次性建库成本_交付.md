### 1.3 非规范事实值（全量扫描，非抽样）

对正式（`c04_facts_80q.json`，18892 键）与开发（`dev_facts_all40q.json`，9770 键）做**全量值类型扫描**，发现 11 个非规范值（既不是字符串列表、也不是空列表）：

| 来源 | 正式 | 开发 | 合计 | 性质 |
| --- | --- | --- | --- | --- |
| 作者缓存（`reused`） | 5 | 3 | **8** | 任务格式复读或单字符串回复被作者抽取器原样存进 facts 字段 |
| 我方管道（`extracted`） | 2 | 1 | **3** | 解析器接受「裸 JSON 字符串」或「元素非字符串的列表」 |

具体明细：

**作者缓存遗留（8，`reused`，非我方责任）**
- `sharegpt_hHGVWPU_4_1` / `sharegpt_TRck0h4_0_3` / `sharegpt_tntUB4J_0_9`：作者缓存存成了 `[{bullet_point…}]`、`[[…],[…]]`、`[{id,fact…}]` 等**结构体列表**（任务输出复读，非事实）。
- `sharegpt_6EDKmvB_0_1` / `sharegpt_8fC32jy_7_2` / `sharegpt_Us25gXO_18_1` / `sharegpt_bUaSM2v_0_1` / `sharegpt_DDnUhPZ_9_6`：作者缓存存成**单个字符串**（"acknowledged" / "READ" / "I acknowledge" / Jar Jar 扮演整句）。

**我方管道泄漏（3，`extracted`，应记录并注意）**
- `sharegpt_n3MgsgL_0_1` / `_0_21`（正式，题 `0977f2af`）：模型扮演 Barney 输出**裸 JSON 字符串**，`parse="direct"` 的 `json.loads` 接受了错误类型，字符串未转列表。
- `sharegpt_XYtuANl_9_2`（开发，题 `505af2f5`）：模型复读任务输出成**字典列表**，C03 未校验元素类型即入库。

**跨线不一致（需注意）**：`sharegpt_XYtuANl_9_2` 是 dev/formal **共享会话**——开发缓存（C03）存了泄漏的字典列表，正式缓存（C04）已正确定案为 `[]`。因此同一轮在 dev K1（B05）与 formal K1（B06）的事实不一致。

**影响评估**：B 线 `B05/prepare_facts.py::normalise()` 按官方读取方式强转——字符串→`[字符串]`、字典→`str(字典)`——所以这些值会以噪声形式进索引但**不会崩溃**；11 条相对 28662 轮可忽略（B06 README 同判「影响可忽略」）。建议后续若重做 C 线，在解析层增加「元素必须是字符串」的校验。

## 2. 事实失败率

口径：**补抽轮** = 作者缓存里 `null`（原解析失败）或 `missing`（版本漂移缺失）而需本机抽取的轮次。分两档：

| 指标 | C02（dev 5题） | C03（dev 35题） | C04（formal 80题） | 合计 |
| --- | --- | --- | --- | --- |
| 补抽轮数 | 21 | 69 | 162 | **252** |
| 首跑解析失败 | 8 | 5 | 19 | **32** |
| **首跑解析失败率** | 38.1% | 7.2% | 11.7% | **12.7%** |
| 正则宽松救回 | 1（7 条） | 1（5 条） | 0 | 2 |
| 人工按作者风格整理 | 0 | 1（11 条） | 3（27 条） | **4** |
| 无事实定案 `[]` | 7 | 3 | 16 | 26 |
| **最终未解析 / null** | 0 | 0 | 0 | **0** |

- 首跑失败率随任务增大先降后升（C02 小样本 8/21 偏高、C03 5/69、C04 19/162）；失败主因是 Q3_K_M 对「拒绝/角色扮演/任务指令/复读 ICL」轮输出非列表 JSON。
- greedy（temperature=0）解码确定性强，重跑结果相同，`max_tokens` 下调也无法打断退化循环，故 4 轮人工整理（C03 1 + C04 3）是最终兜底，占补抽的 **1.6%**。
- 抽取轮在全部就绪轮中的占比：252 / 28,662 = **0.88%**（其余 99.1% 直接复用作者缓存）。
